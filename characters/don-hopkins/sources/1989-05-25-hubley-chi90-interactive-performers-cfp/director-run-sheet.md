# Hubley's director's notes — Empowered run sheet (1990-03-15)

Craig Hubley's response to Don's proposed demo sequence. Hubley rejects "demo" framing and
imposes **drama**: short, emotional, audience chanting, Glenn Gould epigraph, gesture interface
thesis.

Source: Hubley → Don, 15 March 1990, subject *Re: CHI'90 demos*.

---

## Don's draft blurb (rejected as too dry)

> I'll show several kinds of "pie menus"… and "mouse ahead display suppression"… fish-eye view
> through the pseudo-scientific visualizer.

**Hubley:** *"Good but not dramatic enough. This is a performance… not so much about showing
*the system* as it is about showing *you the expert* using it."*

Program copy Hubley wanted instead:

> By pushing the pie-menu interface to the limit you get a **gesture interface** that ties the
> tools so tightly and personally to their user that they effectively become **one cooperative
> entity.**

---

## Act I — Pie menus + mousee

| Don proposed | Hubley directed |
|--------------|-----------------|
| Intro pie menu; explain window mgmt items slowly | **Keep zippy** — assume audience knows window systems; novelty is the **pie menu** |
| Walk through stretch corner slowly | **One** slow demo max, then fast |
| Mouse-ahead; pac-man feedback | Explain: **one pac-man = one level ahead, two = two levels**; go **deeper than CHI'88** (3–4?) |
| Font wheel, color wheel | Use in **manic section before** "impossible feats" |
| — | Build drama: impossible window ops in **one second**; audience **"Go! Go! Go!"** or **"Three! Three! Three!"**; **drumroll** before blindfolded encore |

**mousee:** window showing mouse trail + click marks + menu pop circles — *"very useful for
showing what I'm doing with the mouse."*

---

## Act II — PSIBER Space Deck

| Don proposed | Hubley directed |
|--------------|-----------------|
| Open PSIBER debugger; demonstrate pie menus | **Brief** — bright people should see it's **programming**; hope it doesn't take long to open |
| Deep-dive PostScript dictionary | **Fill the screen** — *"Everybody will identify with that. Pretend to get lost looking for a clock."* |

---

## Act III — Pseudo Scientific Visualizer + finale

| Don proposed | Hubley directed |
|--------------|-----------------|
| Round-window visualizer; click blobs; zoom sub-windows | Risk: **anticlimax after pie menus** if weak; if strong, **2001** baby-Object moment |
| Precomputed zoom animation through X11/NeWS **Object** class hierarchy | Consider **Thus Spake Zarathustra**; or invert order — show **world first**, then empowerment within it |

**Hubley's closing thesis (Glenn Gould):**

> *"In the best of all possible worlds, art would be unnecessary. Its offer of restorative,
> placative therapy would go begging a patient… The audience would be the artist and their life
> would be art."*

Goal: audience leaves believing **every user can be an artist** — not *"when will Windows do that?"*

---

## Hubley's performance philosophy (same letter)

- **Performance ≠ demo.** Don't enumerate how the system works — that's papers and the demo track.
- **Emotional, not technical.** *"Man and machine — how close can they become?"*
- **Practical UI as stage art** beats VR-only spectacle: answers *"what does it do for me?"*
- **VR shouldn't get all the attention** — visual programming without $100k gear can be just as
  exciting to do **and** watch (Aug 1989 thread echo).
