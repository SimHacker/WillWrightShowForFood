## What the tags mean

These are not jokes about ignoring bugs — they are **honest classifications** for a game where
emergent behavior was the product:

| Tag | Meaning |
|---|---|
| **Working as Implemented (WAI)** | Code matches spec; reporter wanted different behavior |
| **Working as (poorly) Designed** | Spec matches code; the design was the bug |
| **Working As Limitedly Understood** | Eric Hedman's extension — we shipped what we comprehended |
| **Screw It, We're Shipping** | Release criterion — Jim Mackraz's addition |
| **Unless it sets the computer on fire or makes us look stupid, it's shipping** | Russ Fan's formulation of the same bar |

**The Look (TM)** — Melissa's face when a developer closed a ticket WAI. Cory Tsang remembers it
specifically. Melissa hopes she's forgiven.

Together this is a **shipping philosophy in five tags**: emergent games produce "bugs" that are
features; the job is distinguishing which is which before the deadline, not after.
